# Учебный сайт на Laravel

Учебный проект по серверной веб-разработке. В лабораторной работе № 9 реализована модерация комментариев к новостям. Сохранены регистрация, аутентификация, роли пользователей, разграничение доступа, CRUD новостей, комментарии и почтовые уведомления, реализованные в предыдущих лабораторных работах.

## Реализовано

- Регистрация и вход пользователей с проверкой введённых данных.
- Хеширование пароля и назначение роли «читатель» новым пользователям.
- Роли «читатель» и «модератор», связанные с пользователями через `role_id`.
- Policy для новостей: читатели просматривают публикации, а модераторы могут создавать, изменять и удалять их.
- Policy для комментариев: читатели добавляют комментарии, а модераторы могут изменять и удалять их.
- Общее правило Gate `manage-articles` для управления новостями.
- Правило Gate `moderate-comments` для доступа к модерации комментариев.
- Комментарии с привязкой к новости и автору.
- Поле `is_approved` для подтверждения модерации комментария.
- Создание новых комментариев со статусом, не прошедшим модерацию.
- Отображение на странице новости только одобренных комментариев.
- Страница очереди комментариев для модератора с действиями «Одобрить» и «Отклонить».
- Сообщение пользователю о том, что новый комментарий ожидает модерации.
- Проверка данных статей через `ArticleRequest`.
- Проверка текста комментария через `CommentRequest`.
- Защищённые маршруты middleware `auth:sanctum`.
- CRUD новостей с пагинацией.
- CSRF-защита state-changing форм.
- Сиды ролей, тестовых пользователей и новостей.
- Mailable-класс `ArticleCreated` для формирования письма о создании новой статьи.
- Отправка уведомлений пользователям с ролью «модератор» после создания статьи.

## Страницы и маршруты

| Адрес | Содержание |
| --- | --- |
| `/` | Главная страница со списком публикаций |
| `/galery/{article}` | Публикация и полноразмерное изображение для авторизованного пользователя |
| `/register` | Форма регистрации |
| `/signin` | Альтернативный адрес формы регистрации |
| `/login` | Форма входа |
| `/logout` | Выход из системы методом `POST` |
| `/articles` | Новости из базы данных с пагинацией |
| `/articles/create` | Форма создания новости для модератора |
| `/articles/{article}` | Просмотр новости и одобренных комментариев |
| `/articles/{article}/edit` | Форма редактирования новости для модератора |
| `/articles/{article}/comments` | Добавление нового комментария |
| `/articles/{article}/comments/{comment}` | Изменение или удаление комментария |
| `/moderation/comments` | Список комментариев, ожидающих модерации |
| `/moderation/comments/{comment}/approve` | Одобрение комментария методом `POST` |
| `/moderation/comments/{comment}` | Отклонение и удаление комментария методом `DELETE` |
| `/about` | Информация о проекте |
| `/contacts` | Контактные данные |

Маршруты новостей и комментариев доступны только после входа. Гости перенаправляются на `/login`. Для авторизованного пользователя действия дополнительно проверяются с учётом его роли.

Страница `/moderation/comments` и маршруты одобрения и отклонения доступны только модератору. Для доступа используется middleware `can:moderate-comments`.

## Роли и разграничение доступа

Роли хранятся в таблице `roles`; у пользователя роль задаётся внешним ключом `users.role_id`.

| Роль | Возможности |
| --- | --- |
| Читатель (`reader`) | Просмотр новостей, просмотр одобренных комментариев, добавление комментариев |
| Модератор (`moderator`) | Все действия читателя, управление новостями, изменение и удаление комментариев, одобрение или отклонение комментариев |

Проверки доступа к новостям и комментариям определены в политиках `ArticlePolicy` и `CommentPolicy`, а разрешения модератора добавляются через `Gate`. Для показа или скрытия элементов интерфейса используются Blade-директивы `@can`. Контроллеры и Form Request проверяют права на сервере независимо от интерфейса.

## Модерация комментариев

В таблицу `comments` добавлено поле `is_approved` логического типа:

```php
$table->boolean('is_approved')->default(false);
```

Поле приведено к типу `boolean` в модели `Comment`.

При добавлении комментария устанавливается значение `is_approved = false`. Комментарий сохраняется в базе данных, но не отображается пользователям до одобрения модератором. После сохранения на странице новости выводится сообщение:

```text
Комментарий отправлен и ожидает модерации.
```

Для модератора в панели навигации доступна ссылка «Модерация комментариев». На странице модерации выполняется выборка только комментариев со значением `is_approved = false`:

```php
Comment::query()
    ->where('is_approved', false)
    ->with(['article', 'user'])
    ->latest()
    ->paginate(10);
```

Для одобренного комментария контроллер устанавливает `is_approved = true`. После этого комментарий становится видимым на странице новости.

При отклонении комментарий удаляется из базы данных:

```php
$comment->delete();
```

Запросы одобрения и отклонения доступны только пользователю с ролью модератора. Повторная обработка уже одобренного комментария возвращает ответ `404`.

На странице новости выборка ограничивается одобренными комментариями:

```php
$article->comments()
    ->where('is_approved', true)
    ->with('user')
    ->latest()
    ->get();
```

## Маршруты и контроллеры модерации

В `routes/web.php` для модерации определена отдельная группа маршрутов:

```php
Route::middleware('can:moderate-comments')
    ->prefix('moderation')
    ->name('moderation.')
    ->group(function () {
        Route::get('/comments', [CommentController::class, 'index'])
            ->name('comments.index');
        Route::post('/comments/{comment}/approve', [CommentController::class, 'approve'])
            ->name('comments.approve');
        Route::delete('/comments/{comment}', [CommentController::class, 'reject'])
            ->name('comments.reject');
    });
```

Класс `CommentController` содержит методы:

- `index` — выборка и вывод комментариев, ожидающих модерации;
- `store` — создание нового комментария со статусом ожидания модерации;
- `approve` — одобрение комментария;
- `reject` — отклонение и удаление комментария;
- `update` — изменение комментария;
- `destroy` — удаление комментария.

Шаблон интерфейса модератора расположен в `resources/views/comments/moderation.blade.php`.

## Комментарии

Модель `Comment` связана с новостью (`Article`) и автором (`User`). Таблица `comments` содержит `article_id`, `user_id`, `content`, `is_approved` и временные метки.

При создании автором назначается текущий пользователь, а новость задаётся вложенным маршрутом. Для изменения и удаления применяются scoped route bindings, поэтому нельзя обратиться к комментарию через маршрут другой новости.

`CommentRequest` проверяет право пользователя на создание или изменение и валидирует текст комментария.

## Новости

Для статей используется resource-контроллер `ArticleController` с методами:

- `index` — список новостей, отсортированный по дате публикации и разбитый на страницы;
- `create` и `store` — форма и создание новости;
- `show` — просмотр новости и одобренных комментариев;
- `edit` и `update` — форма и сохранение изменений;
- `destroy` — удаление новости.

Модель `Article` связана с таблицей `articles` и имеет отношение «один ко многим» с комментариями.

`ArticleRequest` проверяет полномочия пользователя и данные формы:

- `title` — обязательная строка длиной до 255 символов;
- `content` — обязательная строка;
- `published_at` — необязательная корректная дата.

## Почтовые уведомления

Для формирования письма создан класс `App\Mail\ArticleCreated`. В конструктор передаётся объект сохранённой статьи. Метод письма задаёт тему и подключает Blade-шаблон `emails/articles/created.blade.php`.

Письмо содержит заголовок новой статьи, дату публикации и текст статьи.

После сохранения новой статьи контроллер выбирает пользователей с ролью `moderator` и отправляет каждому письмо через фасад `Mail`:

```php
Mail::to($moderator->email)->send(new ArticleCreated($article));
```

Для отправки используется синхронный SMTP-транспорт. Пароли приложений и другие секретные данные не следует добавлять в Git.

## Настройка SMTP

В Laravel настройки почты задаются переменными окружения в файле `.env`. Пример:

```env
MAIL_MAILER=smtp
MAIL_HOST=smtp.mail.ru
MAIL_PORT=465
MAIL_USERNAME=ваш_адрес@example.ru
MAIL_PASSWORD=пароль_для_внешнего_приложения
MAIL_ENCRYPTION=ssl
MAIL_FROM_ADDRESS=ваш_адрес@example.ru
MAIL_FROM_NAME="${APP_NAME}"
```

После изменения `.env` выполните:

```bash
php artisan config:clear
```

Если настройки применяются из конфигурационного кеша:

```bash
php artisan optimize:clear
```

## Миграции и базы данных

Для запуска миграций используйте:

```bash
php artisan migrate
```

Для повторного создания таблиц и наполнения базы тестовыми данными:

```bash
php artisan migrate:fresh --seed
```

> `migrate:fresh` удаляет все существующие таблицы в выбранной базе данных. Используйте эту команду только для локальной или тестовой базы.

## Регистрация и аутентификация

Регистрация реализована в `AuthController`. После регистрации пользователь получает роль читателя и перенаправляется на форму входа.

Вход выполняется стандартным сессионным guard Laravel. После успешной аутентификации идентификатор сессии обновляется. POST-маршрут входа ограничен middleware `throttle:6,1`. При выходе вызываются `logout()`, аннулирование сессии и обновление CSRF-токена.

## Модели и таблицы

- `users` — учётные записи, хеш пароля и внешний ключ `role_id`;
- `roles` — уникальное имя роли и отображаемое название;
- `articles` — заголовок, текст и необязательная дата публикации;
- `comments` — текст комментария, внешний ключ новости, автор и поле `is_approved`.

Пароль автоматически хешируется cast-механизмом модели `User`:

```php
'password' => 'hashed',
```

## Тестовые данные

Команда `php artisan migrate --seed` создаёт роли, тестовые аккаунты модератора и читателя и демонстрационные новости. Пароли тестовых аккаунтов генерируются случайно и выводятся в консоль при запуске сидов.

## Запуск проекта

Требуются PHP 8.3 или новее и Composer.

```bash
composer install
```

Создайте файл `.env` на основе `.env.example`, настройте подключение к базе данных и почтовый SMTP-сервер, затем сгенерируйте ключ приложения:

```bash
php artisan key:generate
```

Примените миграции и заполните базу тестовыми данными:

```bash
php artisan migrate --seed
```

Запустите локальный сервер:

```bash
php artisan serve
```

Откройте адрес, указанный Artisan (обычно `http://127.0.0.1:8000`).

## Тестирование

Запустите тесты проекта:

php artisan test

Feature-тесты проверяют регистрацию и вход, защиту маршрутов, CRUD новостей, права читателя и модератора, создание и модерацию комментариев, отображение только одобренных комментариев, валидацию и отправку почтовых уведомлений.

## Краткое описание для отчёта

В лабораторной работе № 9 в Laravel-приложении реализована модерация комментариев к новостям.

В таблицу `comments` добавлено поле `is_approved`. При создании новый комментарий получает значение `false` и не отображается на странице новости. Модератор получает в панели навигации отдельный раздел со списком комментариев, ожидающих проверки.

Контроллер `CommentController` содержит методы создания, одобрения и отклонения комментариев. При одобрении поле `is_approved` устанавливается в `true`, а при отклонении запись удаляется из базы данных. Страница новости выполняет выборку только одобренных комментариев.

Маршруты модерации объединены в защищённую middleware-группу `can:moderate-comments`. Интерфейс и серверные методы недоступны пользователям без роли модератора.

Сохранены регистрация, сессионная аутентификация, разграничение прав по ролям, CRUD новостей, почтовые уведомления, валидация форм и CSRF-защита.
